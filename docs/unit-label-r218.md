# R218 지도 부대 병력 표시 후보

이전 지도는 출진 시 이름(예: 공손찬 3k)만 표시하여 이후 병력 감소를 보여주지 않았다. 화면 전달용 displayName과 troops만 추가하고, 위줄 지휘 무장명/아랫줄 현재 병력으로 표시한다. 군주·무장·부대 원본 label은 바꾸지 않는다. 무장 없는 적 부대는 기존 이름을 유지하므로 '적병 3k'라는 이름과 실제 병력이 함께 보인다.

동일 이름·병력이면 Sprite/texture를 다시 만들지 않는다. 수치 변경 시 구 label texture/material을 dispose하고 새 라벨로 교체하며 부대 삭제 시에도 label 자원을 해제한다. 시야 필터/부대 선택 판정/전투 규칙/AI/저장 형식은 변경하지 않는다.

## 증거
- 67/67 suite. 새 순수 표시 9assert와 소스 연결 6assert.
- 기존 자연251 진행 저장36을 격리 Chrome390x844에 복원: 공손찬 부대78 실제2633 → 지도2,633명. UI의 실제 턴종료37: 실제2484 → 지도2,484명. 원래 사용자 저장은 건드리지 않았다. 과거 진행 저장+현재 후보이며 새 자연 캠페인이 아니다.
- 390과1280 화면 픽셀 검사: 초상 없는 기존 3D 병사 위에 지휘명·병력이 보이며 선택 패널을 열 필요 없음. 도시·다른 부대와의 전역 겹침 제거/원경 모든 글자 가독성까지 보장하지 않는다. 물리폰 미검증.
- 별도 렌더러 입력만2633→2000으로 바꾼 준비 검사는 라벨 갱신/동일값 재사용/구자원2dispose/삭제 성공. 게임 원본과 저장 문자열 변경 없음. 실제 전투 피해 증거와 섞지 않는다.
- 전체 저장 문자열 reload 동일, pageerror0.
- 최초 후보는 worldUnit 변환에서 병력을 누락해 '병력 미상' 표시. UI 검사로 발견해 화면 전달값을 추가. 이후 예전 R16 소스 검사가 label/type 인접 문자열에 의존해1suite실패; 기존 label/type을 보존하고 새 displayName을 별도 추가한 뒤67/67. 검사 약화 없음.
