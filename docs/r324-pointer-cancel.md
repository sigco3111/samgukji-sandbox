# R324 지도 드래그 취소 복구

## 확인한 문제와 변경
R323 map3d.bindInput은 pointerup만 dragging을 끕니다. 명시 pointercancel 또는 lostpointercapture 이벤트가 발생한 뒤에도 다음 pointermove가 지도를 움직였고, 취소한 짧은 탭의 뒤늦은 pointerup도 선택 함수를 호출했습니다.

R324는 두 취소 이벤트에서 dragging과 pinch 거리 캐시를 비웁니다. 활성 드래그가 없는 pointerup은 선택하지 않습니다. 정상 down/up 클릭, 정상 드래그, 휠, 키 회전의 기존 처리와 전투/이동 규칙은 바꾸지 않았습니다. 다중 포인터 전체 재설계가 아닙니다.

## 검증 범위
동일 자연194 저장을 별도 격리 페이지로 열었습니다. 실제 마우스 down/move 뒤 취소 이벤트만 dispatch한 진단입니다. 브라우저가 자연 발생시킨 취소나 실폰 검증으로 세지 않습니다.

두 이벤트 각각 취소 전후 camTarget: R323은 다음 move에 바뀜, R324는 동일. 정상 새 클릭은 양쪽1회, 활성 down 없는 stray-up은1→0회, 취소 탭 뒤 up은1→0회. 호출 횟수 검사는 onPick을 임시 카운터로 바꿨으므로 실제 도시 선택 성공과 혼동하지 않습니다. 해당 함수 복구 후 실제 도시 좌표 클릭은 양쪽 동일 전경 손씨 부대 패널로 이어집니다. 기존 도시 앞 부대 우선 선택을 유지합니다.

카운터 진단 전후 전체 게임 JSON/저장 문자열 동일, 오류0. 화면에서 취소 뒤 지도 위치 차이를 확인했습니다. 숫자 위치 보존은 로그가 근거이며 정지 화면 하나만으로 시간적 드래그 종료를 증명하지 않습니다. 132/132 회귀 통과. 새 실행 게이트는 정상 클릭, 정상 드래그, 두 취소/상실, 뒤늦은 선택 방지, 새 클릭 복구를 직접 호출합니다.

## 남은 한계
물리 폰/운영체제 취소, 다중 손가락 순서와 전체 pinch 동작은 검증하지 않았습니다. pointer ID별 드래그 관리, 추가 제스처 기능은 추가하지 않았습니다. 게임/AI/경제/초상화660/원래 저장/공개본은 그대로입니다. 기능 구현80% / 검증 포함 완성도60% 유지. R323 시설요약 문구와 모든 선행 수정 및 R180 생산증거 정정도 보존합니다.
