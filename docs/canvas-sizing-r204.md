# R204 캔버스 CSS 크기와 렌더 버퍼 분리, 로컬 후보

## 재현
R203의 map3d.resize는 renderer.setSize(w,h,false)로 렌더 버퍼만 바꾸는데 CSS canvas에는 너비/높이가 없었다. canvas의 intrinsic width/height가 CSS 크기로 사용됐다. 390×844 화면에서 실제 측정:

| 픽셀비 | 수정 전 CSS | 수정 후 CSS | 렌더 버퍼(전후 동일) |
|---|---|---|---|
| 0.5 | 195×422 | 390×844 | 195×422 |
| 2 | 780×1688 | 390×844 | 780×1688 |

저픽셀비에서는 지도 표시가 화면의 일부만 채우고, 고픽셀비에서는 크게 잘리며 카메라 투영과 표시 비율이 달라진다. 이전 검은 지도영역을 단순 소프트웨어WebGL 환경 문제로 단정할 수 없었다. 기존 모달 검증은 유지하되 그 캡처를 지도품질 근거로 쓰지 않는다.

## 변경
CSS #map-canvas width:100%;height:100%만 추가한다. 기존 고정 위치·inset·터치 규칙은 유지한다. main/ai/map3d/index 버전 r204 동기화. 게임 엔진·AI 논리·지도데이터·경제·외교 변경 없음.

## 검증
- 실제 로컬 Chrome 픽셀비0.5와2에서 위 표의 CSS/버퍼 분리 확인.
- 실제 투영 좌표로 마우스 클릭→도시 수동패널 열림, 실제 회전 버튼→도시 클릭, 844×390으로 방향전환→도시 클릭 모두 통과. 픽셀비0.5는 기본 렌더루프, 픽셀비2는 고해상도 소프트웨어WebGL이 조작 타임아웃을 일으켜 시험에서만 requestAnimationFrame을500ms로 제한했다. 정상속도/물리기기 성능 통과 증거는 아니다.
- 390×844와844×390 각 픽셀비의 실제 스크린샷4장 직접 검토. 지도는 화면 전체를 채우고 도시 표시가 유지된다. 저픽셀비 흐림은 낮은 버퍼해상도에 따른 현상으로 고화질 주장하지 않는다.
- CSS 소스게이트5개, 전체52/52스위트 통과. 첫 전체검사의 smoke.mjs 군사 임명은 앞선 무작위 전쟁에서 포로/야전 인물까지 고른 시험 선택 오류였다. 별도 fresh Game의 재직 인물만 고르도록 해당 시험을 격리했다. 군사 실행규칙은 바꾸지 않았다. 첫실패를 숨기지 않으며 단독 재실행/최종전체 통과와 구분한다.
